What moved between a saved column and the release of the day, one block per participant per run
that found something. Prepared by .github/workflows/drift.yml, which runs weekly against today's
versions rather than the ones probe/versions.env pins. A non-empty run leaves a proposed copy and
patch as an artifact; this saved log changes only through a reviewed repository change.

A quiet week leaves nothing here: the run happened, and the workflow's own history says so. This
file is for the other case, where the participant answered differently from the column saved in
results/ - which is not by itself a defect in either. It says when, in what version, and on which
cases, so that "when did this cell change" is a question to git log rather than to memory.

The block header is the day, the participant, and the revision it was actually built from. A
participant is named by its column's path under results/: DUCKDB is results/DUCKDB.txt, and
relations/DUCKDB is results/relations/DUCKDB.txt. The line under it is the revision of this
repository and one fingerprint over what this side fed the comparison - the plans, expected.json and
normalize.py for the 98-plan corpus; the bundles, the extract and the code that writes a column for
the relation corpus. Without those two a moved answer, a regenerated corpus and an edited
expectation cannot be told apart afterwards.
