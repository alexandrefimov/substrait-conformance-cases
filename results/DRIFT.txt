What moved between a saved column and the release of the day, one block per participant per run
that found something. Written by .github/workflows/drift.yml, which runs weekly against today's
versions rather than the ones probe/versions.env pins.

A quiet week leaves nothing here: the run happened, and the workflow's own history says so. This
file is for the other case, where the participant answered differently from the column saved in
results/ - which is not by itself a defect in either. It says when, in what version, and on which
cases, so that "when did this cell change" is a question to git log rather than to memory.

The block header is the day, the participant, and the revision it was actually built from. The line
under it is the revision of this repository and one fingerprint over the corpus, expected.json and
normalize.py: without those two a moved answer, a regenerated corpus and an edited expectation
cannot be told apart afterwards.
